What this is, and what it is checked against

Two solvers, matching two Python modules line for line rather than illustrating them. theoryRun is particlesim.cosmo.dynamics.evolve: it integrates H' = −(3/2)(1+w)ρ f'(ρ) with the plugin's own H² = f(ρ), second order so that a bounce — where f = 0 and √f has a branch point — is crossed rather than stopped at. The constraint H² = f(ρ) is monitored rather than imposed, and its drift is in the table. lcdm is particlesim.cosmo.background.Cosmology, with the same two substitutions carrying the accuracy: distances over ln(1+z), ages over s with a = s².

The page is not the authority on whether it agrees. friedmann.js is loaded by the test suite and its numbers are compared with the Python solvers directly: the bounce density to a part in a hundred thousand, and the ΛCDM ages and distances to a part in a billion. Where the page reports a difference from a known value — the loop-quantum critical density, say — that is the fixed-step integrator against the root of H²(ρ), and it converges as the square of the step because the turning point is located by interpolation.

Two things this deliberately does not do. It does not follow a general-relativistic collapse to a = 0: no fixed step can, and the run ends where the monitored constraint says the method has lost the solution, which for a collapse is the same statement as the singularity. And it does not use Gauss-Legendre quadrature, as the Python does; on integrands this smooth, Simpson's rule on the same substituted variables reaches the same answer to twelve digits.
